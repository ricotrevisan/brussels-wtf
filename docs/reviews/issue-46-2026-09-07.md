## Standards

Four original findings, each grounded in documented standards:

1. **P1, open — Role, scope, and reporting period are not proven.**
   `identity/trusted_verifier.ex`, `direct_declaration_evidence?/3`, accepts a
   matching line anywhere in the text and compares only URL/location years.
   `identity/ixelles_mandate_declaration_processor.ex`, `record_fact!/5`, converts
   any parsed mandate row into a generic person-to-Ixelles fact. Specification
   §5 requires “exact person and role row, table scope, and reporting period”.
2. **P1, open — Name substring matching violates exact identity.**
   `TrustedVerifier.contains_name?/2` removes all boundaries, so “Alex Example”
   matches “Alex Exampleson”. `CONTEXT.md`, Person, requires an explicit
   identifier or an exact name plus independent corroboration. Parse and compare
   the complete declarant name; a prior mandate cannot prove a longer name is
   the same person.
3. **P1, fixed — OCR escaped the isolated queue.** The declaration worker used
   `:enrich` and OCR also reran from discovery callbacks. It now uses `:ocr`;
   discovery consumes the hash-checked immutable artifact and the trusted
   verifier recomputes OCR once in the isolated worker. ADR 0001 requires
   isolated OCR at concurrency one. An independent follow-up review found no
   new blocker in this fix.
4. **P2, open — Unresolved identities lack review cases.**
   `record_row_candidate/4` silently ignores zero identity matches. Candidates
   without corroboration remain unqueued. Specification §5 requires identity
   uncertainty to create an actionable review case and publish nothing.

No heuristic code smell was prioritized over these documented violations.

## Spec

Five original findings plus missing acceptance coverage:

1. **P1, open — Exact role and public presentation are missing.** Issue requires
   an “exact neutral role label” under “Verified facts”. The projection drops
   the declared body/role and the existing renderer says “Public mandate” under
   “Verified public relationships”. Store and render source-native semantics,
   reporting period, claim-level citation, and separate dated history.
2. **P1, open — Invalid documents can pass.** The verifier checks neither scoped
   declaration boundaries, signed attestation, draft/template status, nor
   content reporting year. The passing fixture has no attestation or content
   year. The accepted access spike explicitly says “reject a declaration that
   is filled but unsigned”. A representative approved fixture must prove a
   filled, signed declaration and tie its declarant to the exact scoped row.
3. **P1, open — Identity matches substrings.** This violates the specification's
   “exact name plus an independent corroborating fact” requirement, as detailed
   on the Standards axis.
4. **P1, open — Corrections do not supersede automatically.** `record_fact!/5`
   does not set `supersedes_id`; `TrustedVerifier.validate_supersession!/2`
   rejects a replacement when a current fact exists. Issue requires “a
   corrected/new report supersedes status without erasing evidence history”.
   Add explicit predecessor selection and correction/history scenarios.
5. **P1, fixed — Corroboration recursed into the declaration itself.** The
   unpublished issue-46 migration now uses `CASE` to dispatch by verifier and
   allows corroboration only through the independent minutes verifier,
   excluding the same fact ID. The regression invalidates the minutes source
   and asserts the declaration becomes untrusted and disappears from the public
   projection. An independent follow-up review confirmed the minutes predicate
   remains unchanged and recursion is bounded to the minutes branch.

**Acceptance coverage remains incomplete:** the integration fixture precreates
source versions rather than driving acquisition, and checks a projection rather
than an HTTP-rendered person page. Add acquisition, multilingual routes, feeds,
navigation/indexing, invalid/draft/template/header/period/drift, and corrected
version scenarios. No scope creep was identified.
